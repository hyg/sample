# 配合测试：一步一步来

目标：**用你本机的节点，和我沙箱里的节点，跑一次真实的跨 NAT 打洞**。
两边都在真实 NAT 后面，这是唯一能验证"打洞真的有效"的方式。

---

## 0. 你需要什么

- **Node.js ≥ 18**（`node -v` 确认）。不需要 `npm install` —— 这个项目零第三方依赖。
- 一个能上外网的网络（要能发 UDP，公司和校园网偶尔封 UDP）。
- 约 5 分钟。

检查 Node 版本：

```bash
node -v      # 需要 v18.0.0 或更高
```

---

## 1. 解压

```bash
unzip p2pnode-1.0.0.zip
cd p2pnode
```

目录里应该是：`bin/  src/  docs/  test/  README.md  package.json`。

---

## 2. 可选自检（30 秒，不需要外网）

```bash
node test/integration.test.js
```

应当看到 `全部测试通过 ✅`。这一步只验证代码在你机器上能正常跑；
它跑的是本机回环，**不涉及 NAT，不代表打洞能成功**。

---

## 3. 启动节点（关键）

```bash
node bin/p2pnode.js --network p2p-live-test --secret "live-test-2026-9f3a2b7c1d5e" --port 6881 --log debug
```

> Windows PowerShell / CMD 用法完全一样。
> 若 6881 被占用（很多 BT 客户端会占），把 `--port 6881` 改成 `--port 0` 让系统随机分配。

启动后会打印：

```
节点已启动
  peerId : xxxxxxxxxxxx
  UDP    : 6881
```

然后等 10~20 秒，关注这三类日志：

| 日志 | 含义 |
|---|---|
| `STUN: 2/4 响应，映射 1.2.3.4:56789 NAT=endpoint-independent` | 你的出口映射和 NAT 类型。`endpoint-independent` = 锥形，成功率高 |
| `DHT: 发现节点 5.6.7.8:12345` | 从公共 DHT 上看到了对端（第一个是我沙箱里的节点） |
| `已连接 peer=xxxx @ 5.6.7.8:12345` | **打洞成功，链路建立** |

---

## 4. 我们怎么配合

**两边必须同时在线**，否则互相看不见。所以：

1. 你按上面启动，保持窗口不要关；
2. 回我一句"起来了"（顺便贴上你的 `peerId` 和 `STUN: ...` 那行）；
3. 我在沙箱里用**同样的 network 和 secret** 启动对端，跑 40~60 秒；
4. 你把这几行贴给我（或直接说没反应）：
   - `STUN: ...` 那行
   - `DHT: 发现节点 ...` 有哪些
   - 有没有 `已连接`
5. 我这边也贴我的日志，两边一对就知道卡在哪。

> 如果 60 秒内一直是 `DHT: 发现节点` 而没有 `已连接`，那就是**地址成立但穿不透**，
> 属于对称 NAT 的正常结果（我在沙箱里测出来就是 `address-dependent`）。

---

## 4.5 手动指定对端（跳过 DHT，最可控）

如果 DHT 上噪音太多、或者想排除"发现环节"的干扰，可以直接指定对端地址：

```bash
node bin/p2pnode.js --network p2p-live-test --secret "live-test-2026-9f3a2b7c1d5e" \
  --port 6881 --peer 1.2.3.4:5678 --log debug
```

`--peer` 可以写多次。这样不依赖 DHT，启动就开始向该地址打洞。

**怎么判断"我的包到底有没有到达对方"**：对方日志里会出现

```
DEBUG 收到打洞包 ← 你的IP:端口
```

每个来源只打印一次。有这行 = 包到了；没有 = 包在路上就被丢了（防火墙 / 运营商 / 地址不对）。

## 5. 三种结果分别说明什么

| 现象 | 结论 |
|---|---|
| 出现 `已连接` | **打洞成功**，真实跨 NAT 直连。接下来可以 `/send all 你好` 互发消息 |
| 有 `DHT: 发现节点`，但一直没 `已连接` | 地址交换成功、穿透失败 → 至少一侧是对称 NAT，物理限制，不是 bug |
| 完全没有 `DHT: 发现节点` | 连 DHT 都没进去，多半是 UDP 出网被封（公司/校园网），或引导节点全不可达 |

---

## 6. 试试发消息（连通后）

在同一个窗口输入：

```
/send all 你好，这是我本机发的
```

对方会打印 `<xxxxxx> 你好，这是我本机发的`。

其他命令：`/peers`（已连接列表）、`/status`（NAT 详情）、`/find`（立刻再找一轮）、`/quit`。

---

## 7. 退出时会给你 BOOTSTRAPS

输入 `/quit` 或按 Ctrl+C，会打印本次运行中**逐个 ping 验证过**的可用节点：

```
const BOOTSTRAPS = [
  { host: '122.193.252.163', port: 37761 },
  ...
]
```

同时写入 `data/bootstraps-latest.json`，下次启动会自动加载 —— 所以第二次运行会更快。

---

## 8. 常见问题

**Q：Windows 弹出防火墙提示？**
允许"专用网络"即可。我们是主动出向打洞，通常不放行入站也能通。

**Q：端口被占用 `EADDRINUSE`？**
换 `--port 0` 或 `--port 7000`。

**Q：公司网/校园网完全没有 `发现节点`？**
大概率 UDP 出网被拦。换个网络（手机热点）再试一次就能确认。

**Q：想换一个别人不知道的网络？**
`--network` 和 `--secret` 都换掉即可，两者一起决定"谁能看见谁"。
测试用的这组参数在对话里公开过，测完请换掉。

**Q：`data/` 目录里是什么？**
你的长期身份私钥（`identity.json`）、DHT 节点 ID、退出报告。删掉会生成新的 peerId。
